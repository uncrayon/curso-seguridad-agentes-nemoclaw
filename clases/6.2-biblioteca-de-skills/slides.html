Anatomía de un SKILL.md

skill-library/diagnostico-api/SKILL.md
frontmattername: diagnostico-apidescription: Diagnostica errores 401, 429… Úsala cuando el usuario pegue un error de la API.
Pasos
  1. Extrae el código del error.
  2. Usa la herramienta diagnosticar_http.
  3. Responde: qué pasó, la causa y qué hacer.
Límites

Nunca muestres la key completa.

label
La etiqueta (frontmatter)nombre y descripción · el agente siempre la ve
list
La recetapasos numerados · solo si la elige
block
Los límiteslo que nunca debe hacer

Clic 1: la etiqueta (frontmatter, entre dos líneas ---): nombre y descripción; es lo que el harness ve siempre. Clic 2: la receta (runbook): pasos numerados, con la herramienta exacta. Clic 3: los límites; el texto los pide, ya veremos quién los impone. El cuerpo lo ve el modelo solo si elige la skill. Muéstrala 20 segundos: es la que capturan.

Que funcione la explícita no prueba que funcione la automática.

Clic 1: explícita, tú la nombras (/diagnostico-api ...); casi nunca falla. En el laboratorio es cuando le das la ruta del SKILL.md. Clic 2: automática, el modelo compara tu pedido con las descripciones; falla si la descripción no dice cuándo usarla. En el laboratorio es cuando omites la ruta. Clic 3: NVIDIA lo advierte en su lección 03c: el ejercicio con la ruta "no demuestra la selección automática".

La description es el disparador

labeldescription: Herramienta útil.
searchNadie la eligeno dice cuándo usarla
labeldescription: Diagnostica errores 401, 403… Úsala cuando el usuario pegue un error o diga «el modelo no responde».
check_circleLa encuentra solael pedido coincide
Qué hace+Cuándo usarla+Las palabras del usuario

Clic 1: una descripción vaga ("Herramienta útil") no dice cuándo usarla: nadie la elige. Clic 2: la útil, con sus tres partes marcadas. Clic 3: qué hace + cuándo usarla + las palabras del usuario. Una description no es un título: es una regla de enrutamiento.

Clic 2: en la VM TERMINAL del tablero, el curso ya está clonado en ~/curso desde antes (si no, git clone --depth 1 https://github.com/uncrayon/curso-seguridad-agentes-nemoclaw ~/curso). Clic 3: nemoclaw my-assistant skill install ~/curso/skill-library/diagnostico-api/; responde ✓ Validated SKILL.md e Installed diagnostico-api from path -> …; confirma con nemoclaw my-assistant skill list. Clic 4: sesión nueva y prueba las dos selecciones: nemoclaw my-assistant agent --session-key prueba-62a -m '…' o el botón CHAT WITH AGENT. Es opcional y va al final de las prácticas del laboratorio. Clic 1: tu biblioteca, con una skill envenenada escondida. Clic 2: una skill envenenada es una directiva envenenada que sobrevive entre sesiones. Conecta con la trifecta letal: la persistencia hace que una inyección dure más que una conversación.
